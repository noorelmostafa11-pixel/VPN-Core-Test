المسار الأصلي يقرأ JSON أولًا ويحتفظ بالمعالجة الموجودة بالفعل. المسارات الجديدة لـextra تُجرّب فقط عندما بقيت القيمة نصًا غير مقبول، وتشترط الحصول على كائن كامل. تحفظ `+` و`%` والاقتباسات داخل النصوص، ولا تنفّذ تعبيرات أو تستكمل JSON مبتورًا. الصيغ البديلة تخضع لنفس فحوص الخيارات والنقل والتشفير والشهادات.

يحفظ `Config.original_uri` الرابط الأصلي، ويحفظ `original_options` مفاتيح المصدر وقيمه. مفاتيح REALITY الأصلية المسبوقة بـ`;` تبقى محفوظة؛ أسماء التوافق تُضاف إلى خيارات التشغيل دون استبدال أي اسم صريح موجود. تعرض تقارير الفحص أسماء مسارات المعالجة في `uri_compatibility` فقط، دون قيم الروابط أو المفاتيح. حساب `node_id` يظل من الرابط الأصلي.

## اختبارات الإضافة

`tests/test_uri_compatibility.py` يتحقق من حفظ المصدر والقيم، وأولوية الحقول الصريحة، ورفض JSON المبتور والتشفير المجهول والمفتاح الناقص وshort ID الخاطئ. أُضيف إلى `tests/test_xhttp_modes.py` اختبار نقل بيانات فعلي عبر TLS وHTTP/2 وVLESS لكل صيغ extra الأربع، باستخدام قرين مستقل ونقل 100,019 بايت لكل صيغة. البناء والاختبارات المحلية لا تشغّل GitHub Actions.

التحقق شمل 213 حالة في حزمة الاختبار: 211 ناجحة واختبارا خادم Trojan المرجعي الخارجي مستثنيان لعدم توفيره. أُعيدت الفحوص المتأثرة بعد إعادة بناء قرين QUIC المحلي ذي الملف المبتور وضبط `script_revision` على 0.4.8؛ نجحت الحالات العشر المعادة. ونجحت ثماني حالات إضافية على بناء Linux للإنتاج، تشمل البروتوكولات الأربعة والتحقق من الشهادة وواجهة C المشتركة وصيغ XHTTP الجديدة.

قبول الإعدادات ليس قياس نجاح الإنترنت أو سرعة الكور واستهلاكه. لا يُستعاد محتوى الحقول التي وصلت قيمتها `{` فقط، ولا تُحذف FinalMask أو extra لتحويل العقدة إلى إعداد مختلف.
