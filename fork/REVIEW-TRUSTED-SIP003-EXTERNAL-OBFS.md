# Locally trusted SIP003 and authentic simple-obfs integration

Parent 57320ebefcf680286f1de96ef740d365971f0439. This is an opt-in APP-ONLY interface, not a change to normal Shadowsocks links. A caller-approved hash-pinned executable is started using SIP003 SS_LOCAL_HOST/PORT, SS_REMOTE_HOST/PORT and SS_PLUGIN_OPTIONS. The original Shadowsocks engine connects on local loopback, letting the real external obfs-local simple-obfs implementation supply HTTP/TLS obfuscation, or a real approved v2ray-plugin supply its mux/QUIC framing. No fake WS alias for default mux, no arbitrary executable from a remote URI, no trust-policy downgrade and no automatic plugin download.

API: conf.ParseNodeURIWithTrustedSIP003(ctx, rawLink, sip003.Approved{ Name:"obfs-local",Executable:"/absolute/preinstalled/obfs-local",SHA256:"...hex..." }) returns outbound and closer. App must retain closer for plugin lifecycle and only select this API after explicit local authorization. Supported remote obfs parameters are obfs=http|tls and optional obfs-host; external v2ray-plugin accepts controlled tls/mode/host/path/mux. Unknown third-party plugins take locally owned option strings only, never arbitrary remote option flags.

The SIP003 supervisor's readiness probe can create an empty loopback connection; independent plugin compatibility must validate this behavior. Local port allocation has a bind/close/rebind interval, so loopback ownership is not intrinsically authenticated. These are staged app-integration caveats to verify in the level-3 gate. No plugin binaries are packaged or executed during development. Full Go1.27.1 build and peer wire tests NOT_VERIFIED.
